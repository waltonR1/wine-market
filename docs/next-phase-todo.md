# Wine Market 后续开发与联调上线总清单

更新时间：2026-03-28

## 1. 文档目的
这份清单用于整理当前项目从“现阶段功能开发”到“后端联调”再到“上线交付”的完整待办范围。

目标不是只列功能点，而是把以下几类事情都纳入：
- 页面与业务功能补全
- 数据结构与接口契约收口
- mock 与真实后端切换准备
- 联调前准备
- 联调过程中的问题闭环
- 上线前检查项
- 上线后观测与回滚准备

## 2. 当前已完成基线
当前项目已经具备的基础：
- 基础商城浏览链路已打通：首页、分类、列表、详情、购物车、下单、订单列表、订单详情、支付页
- 订单模块已具备基础闭环：支付、取消、确认收货、评价、追评、再次购买、售后占位与基础流程
- `config/env.ts`、`config/app.ts` 已建立显式配置结构
- 颜色语义化体系已建立，并已接入高频页面
- 订单调试工具已接入，可继续作为 mock / test 阶段内部工具使用

当前仍明显不足的部分：
- 用户系统未形成完整闭环
- 商品系统缺少搜索、筛选、排序、推荐
- 个人中心大部分页面仍偏占位
- 首页后续需要重做，但方向未最终确定
- 评论系统后续应改为“按订单中的每个商品分别评论”
- 真实微信支付、真实物流、真实鉴权、真实接口联调尚未开始

## 3. 必须持续遵守的项目约束
- 页面层不直接调用 `api/modules`
- 页面层不直接依赖 `API_PATHS`
- 页面只通过 hooks 调业务
- API 请求只放在 `api/modules/*`
- 订单状态规则统一放在 `utils/order.ts`
- 订单状态同步统一收口在 `hooks/useOrder.ts`
- `types/model/*` 只放业务模型
- `types/api/*` 只放接口契约
- 优先增量修改，不为重构而重构

## 4. 推荐推进顺序
建议按下面顺序继续推进：
1. 用户系统补全
2. 商品系统增强
3. 评论系统按商品拆分
4. 购物车与下单链路增强
5. 订单与售后深化
6. 首页重做与运营能力
7. 配置体系、接口层、数据结构收口
8. 真实业务接入
9. 联调阶段
10. 上线准备与发布

## 5. 阶段一：用户系统补全
目标：让登录、个人中心、订单统计、收藏、优惠券、足迹、地址、设置等形成真实闭环。

### 5.1 登录与鉴权
- 完成登录页真实交互
- 明确登录态存储方案
- 完成未登录拦截与跳转回流
- 完成退出登录
- 明确 token / session 失效处理
- 为后续真实后端联调预留统一鉴权注入点

### 5.2 个人中心首页
- 展示真实用户信息
- 接入订单状态统计
- 接入常用业务入口
- 处理未登录态展示
- 处理登录中、空数据、失败态

### 5.3 用户资产与内容
- 收藏列表、取消收藏、跳转商品详情
- 优惠券列表、状态区分、订单页占位联动
- 足迹列表、清空足迹、回到商品详情
- 钱包、积分、推广页补齐最小可用交互

### 5.4 用户资料与设置
- 个人信息编辑
- 实名认证基础交互
- 发票信息管理
- 地址管理完整闭环
- 设置页：清理缓存、退出登录、账号说明

### 5.5 阶段验收
- 登录后个人中心数据正确展示
- 未登录时受限页面有统一处理
- 订单统计与订单真实状态一致
- 收藏 / 优惠券 / 足迹不再只是占位页

## 7. 阶段三：评论系统升级为“按商品评论”
目标：把当前整单评论，升级为“订单中的每个商品单独评论”。

### 7.1 模型与接口
- 重新设计订单评论数据结构
- 每个订单商品独立拥有评分、内容、图片、匿名状态、追评
- 商品详情评论只聚合该商品自己的评论
- 保持订单详情仍能看到本单评论汇总

### 7.2 页面与交互
- 订单评价页改为按商品拆分表单
- 支持单商品星级、文案、图片、匿名
- 追评也按商品维度处理
- 已评价订单详情支持逐商品查看评论

### 7.3 mock 与后端契约
- 调整 `db.json` / mock 评论结构
- 调整商品评论同步逻辑
- 调整订单评论回写逻辑

### 7.4 阶段验收
- 一笔多商品订单可分别评论
- 商品详情评论区只显示对应商品评论
- 订单详情能看到该订单下各商品评论情况

## 19. 建议的执行节奏
建议按以下节奏推进：
1. 先补用户系统与商品系统主链路
2. 再升级评论、购物车、订单、售后
3. 首页重做在方向明确后单独推进
4. 然后做配置 / 类型 / mock / 接口统一收口
5. 再进入真实业务接入
6. 最后进入联调、测试、上线准备
